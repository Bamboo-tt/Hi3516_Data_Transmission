## 16.7 协议原始资料

第 08、09 章引用以下标准解释协议字段，项目实际调用仍以当前 C 源码为准：

- [RFC 3550](https://www.rfc-editor.org/rfc/rfc3550)：RTP 基本头、序号、时间戳、SSRC 与 RTCP。
- [RFC 7798](https://www.rfc-editor.org/rfc/rfc7798)：H.265 的 RTP 负载、FU 与访问单元标记。
- [RFC 6184](https://www.rfc-editor.org/rfc/rfc6184)：H.264 的 RTP 负载与 Marker 语义。
- [RFC 2326](https://www.rfc-editor.org/rfc/rfc2326)：当前简易库所对应的 RTSP/1.0 请求及 TCP interleaved 背景；不据此宣称它实现了标准所有能力。

阅读标准后仍要问：源码是否实现了这个分支、是否保留了要求的字段、失败时有没有维持状态？“协议规定应如此”与“本程序已如此”是两层结论。

## 16.8 自查与回答要点

**问题 1：在索引中找到 `thread_start` 后，接着该查什么？**

回答要点：查全部写入者、读取者、创建失败、worker 自退与 stop/join 的分支。变量名不能证明它同时正确表达创建、运行、停止与回收状态。

**问题 2：发现注释与实际赋值不同，文档应采用哪一项？**

回答要点：以活动代码为当前实现证据，说明命名/注释差异；如果涉及硬件协议，则再用配套 SDK 和运行证据确认，不能自行把代码改写成注释想表达的状态。

**问题 3：如何避免读了正式 SDK 资料后补出不存在的项目调用链？**

回答要点：资料解释接口语义，源码证明调用选择，构建记录证明参与产物，板端记录证明执行与效果。沿这四层建立对应关系，缺哪一层就明确保留边界。
