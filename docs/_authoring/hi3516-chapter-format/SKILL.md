# Hi3516 文档呈现

先读 [AGENTS.md](../../../AGENTS.md) 的公共写作标准和目标全文，确认本次允许改正文还是只读审阅。内容关系按 [hi3516-project-storyline](../hi3516-project-storyline/SKILL.md) 确定；格式不替代事实核查。

## 让形式对应关系

连续解释优先用自然段。一个段落只承担主要的一步推导，但保留“因此、随后、此时、如果”等必要衔接。长段同时包含前提、正常路径和异常时，应按解释任务拆开；不要拆成互不关联的短句条目。

| 内容关系 | 合适的呈现与检查点 |
| --- | --- |
| 两条主线或同类参数的差异 | 表格保持同一维度，注明入口、通道、单位和配置/实测属性 |
| 有严格先后的操作 | 编号步骤交代执行者、前提、结果；并行构建和线程不能硬排成串行 |
| 地址、平面、偏移、持有窗口 | 紧凑文本图或 Mermaid，名称对应代码；示意地址不冒充实测 |
| 请求、状态或资源交接 | 时序图/状态图/数据图选一种合适形式，正常路径后再展开失败 |
| 关键推导结果 | 适度加粗一句核心结论，推导仍放在邻近正文 |
| 大量风险和验证点 | 按同类触发条件汇总，不让表格取代对复杂机制的解释 |

标题按根规则分级。图前先说明读图对象，图后解释箭头的意义和限制；图中写“绑定”还是“字节复制”必须有明确依据。图用于减少读者追踪成本，简单关系不强制配图。

## 代码、命令与练习

代码围栏使用 `c`、`bash`、`powershell`、`makefile`、`text` 或 `mermaid` 等实际类型，保留 Makefile Tab。代码前给运行环境、输入和目的，代码后解释新增机制、结果及失败/回收。仅作说明的节选不得标为可直接运行程序。

命令使用当前真实路径或明确标记的占位符；可写安全的只读检查建议，不因排版任务执行板端操作。保留影响结论成立的条件，不能把条件全部移到章末而让正文变成无条件断言。

练习先列所有题目和必要输入/条件，然后用对应编号集中给参考答案。算例要能够复算，回答讲推理和边界，不能仅重复题干。格式维护不自动要求每章新增练习；整套重写保留原有练习涉及的知识点。

## 检查实际成稿

顺读本章与相邻章，检查标题跳级、列表续号/缩进、表格分列、围栏语言、公式、转义和链接。检查 UTF-8，源码路径用仓库内相对链接，函数名称便于搜索；外置 SDK/PDF 链接在资料索引集中说明克隆后补齐条件。

使用可用 Markdown 渲染器检查输出，并查看有代表性的长章、表格、代码与图。解析成功不等于视觉布局已验证；没有图解析器或预览条件时如实写明限制。检查发现具体问题再局部修复，不按固定次数重写。

修改任务交付实际改善与检查结果；只读审阅给出具体位置、问题、影响和最小修改建议。保留所有重要知识、公式、代码机制和验证边界，不以文档变短作为完成标准。
