# Hi3516 项目贯通

读取仓库 [AGENTS.md](../../../AGENTS.md) 中的任务边界和公共写作标准。本文负责内容组织；呈现时配合 [hi3516-chapter-format](../hi3516-chapter-format/SKILL.md)。两份文件可直接从仓库读取，不要求全局安装。

## 选择真实对象，再建立主干

先核对当前请求与差异。梳理方案交付规划，正文重写交付完整正文，局部维护只修改问题与直接受影响的解释。用户已经给出的正文授权持续有效，不因工作记录中的旧阶段而停止。

阅读 [编写蓝图](../编写蓝图.md) 定位前后章，再从 [源码与资料索引](../../Hi3516CV610_项目学习/16_关键源码与资料阅读索引.md) 进入当前代码。以一个问题贯穿全文：Sensor 的图像经过哪些转换，谁在何时取得使用权，接收端最终为什么能或不能还原画面？

分别追踪三条流程：开发机怎样形成配套产物，板端怎样初始化可工作的资源，运行时怎样持续交接图像与码流。跨层连接要有实际产物或调用证据。不要把启动器、内核、应用画成同一次串行编译，也不要把初始化函数列表写成每帧由 CPU 顺次执行的处理。

## 沿生产者与消费者核查

对 A 从 `new_main2.c` 的 `main` 向 Sensor、SYS/VB、VI/ISP、VPSS、VENC、`processStream`、`sendPacket`、`transmit` 追踪。对 B 从 `sample_venc_rtsp` 向公共辅助层、VENC worker、RTSP session、RTP queue 和客户端游标追踪。阅读返回值与释放点，不只读函数声明或正常调用。

遇到以下容易混淆的边界时，补读双方实现：

| 边界 | 要核实的契约 |
| --- | --- |
| Sensor ↔ MIPI/ISP | 控制总线、lane、RAW 位宽、模式、时序、回调注册与寄存器更新 |
| VI/VPSS ↔ 缓冲 | 尺寸、颜色布局、stride、压缩、online/offline、wrap、depth 与编号 |
| VENC ↔ 应用 | 描述符容量、offset/len、PTS、SDK pack 与 NAL/访问单元的关系、Get/Release |
| 应用 ↔ 网络 | RTP 字段、分片与 Marker、同步读取/复制、发送返回值、排队和丢弃 |
| RTSP session ↔ 客户端 | INIT/READY/PLAYING、共享队列与独立游标、事件驱动位置、TCP 续写 |
| worker ↔ 清理 | 创建成功、运行标志、停止请求、执行结果、join 和对象销毁顺序 |

源码中的活动赋值优先于注释。Makefile 缺省值要查覆盖入口；资料中的开发板、历史脚本与无线派生程序分别说明。没有配套证据时，把疑问精确落到 SDK 版本、构建宏、板端日志或接收侧契约，避免整段含混。

## 把机制讲到可以推导

每章先承接前章已产生的对象，再说明尚未解决的约束。重要概念随问题出现：原始帧太大才引入编码；帧不能独占所有缓冲才解释归还；一个 NAL 超过网络预算才解释 FU；客户端进度不同才解释共享队列和游标。

先讲正常路径，让读者认识对象；随后在同一对象上展开失败、并发与性能。用可复算的小例子说明字节量、stride、包数、帧间隔或队列时长，写明假设，不能将算术值称为实测。代码仅摘足以说明条件与状态的部分，变量来源、失败和回收不能省略到产生错误理解。

重写前记录旧文的重要知识点，在 [编写蓝图](../编写蓝图.md) 对应主题中检查去向。可以合并重复解释、修正错误、调整章节重心；不能只压缩成摘要，也不能用增加术语与表格制造深度。配置对照只维护必要的一份，细节链接到所属章。

## 维护与完成标准

全局架构说明回答职责、拓扑和风险；学习正文展开因果与底层机制；讲解提纲检验是否能连续复述；索引帮助回到生产者与消费者。四种材料互相连接，不整段复制。

先完成已授权内容，再做一轮针对性检查：章节依赖、核心契约、算例、来源、格式和保护范围。检查见格式 skill；本次事实与检查结果写入 [工作记录](../工作记录.md)，不把过程流水账放入读者正文。明确区分本机文档检查、离线逻辑检查、交叉编译、板端运行和接收/现场验证。
